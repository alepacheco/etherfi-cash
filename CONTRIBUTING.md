# Contributing

Keep this a small client for the Ether.fi Cash website API. Changes should have
an independently useful API use case and a focused test. Financial categorization,
database syncing, dashboards, and application-specific policies belong in consumers.

Run `npm ci` and `npm run check`. Build output is generated by TypeScript and is
included in release tarballs, not committed. CI runs the tests on Node 22 and 24.

Use invented account identifiers, merchants, and transactions in fixtures. Never
attach session cookies, wallet keys, card numbers, or raw account responses to
an issue or pull request. Describe observed field shapes with synthetic examples.

For API changes, document the endpoint and the response shape you actually
observed. Separate observations from assumptions. Preserve unknown fields and
status strings, and fail clearly when required response structure changes.

The initial scope is read-only. Do not add automated login, CAPTCHA handling,
session renewal, transfers, or card mutations as part of an unrelated change.
